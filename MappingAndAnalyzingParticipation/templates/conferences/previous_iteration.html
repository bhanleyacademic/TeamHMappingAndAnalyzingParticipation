Project lineage

NetworkMap — Previous Iteration

Before this platform, a student team (Team K) built NetworkMap: a web application for collecting participant data at live events and converting it into network-ready exports. That work established the core problem statement — how do you get from a conference sign-in sheet to a social network graph? — and demonstrated one viable answer. This platform picks up where it left off, extending the pipeline toward rigorous analysis and reproducible visualization.

What Team K Built

Form builder + collection
Admins create custom event registration forms with a shareable URL. Fixed fields (name, org, sector, location, contact) plus admin-defined custom fields. Responses stored in MongoDB in real time.
Self-reported connections
Participants record up to 5 organizational connections per submission, each with a connection type (Met for first time, Reconnected, Shared info, Funding, Referral, Other) — capturing declared relationships, not just inferred co-attendance.
Network export
Responses convert to Gephi- or Kumu-compatible nodes.csv and edges.csv. Two edge types are produced: attendance edges (org → event) and connection edges (org → org). Visualization itself happens in external tools.
Educational content
A /learn section walks users through network analysis concepts, and an /examples page shows static Kumu/Gephi visualizations — making the tool useful for teaching the methodology, not just running it.

How This Platform Extends It

NetworkMap (Team K) This platform
Data scope Live event collection, new data only 25-year longitudinal dataset (1994–2015, 42 events)
Sector taxonomy 6 generic options (Education, Business, Non-profit, Government, Community, Other) 11 canonical SNA categories mapped from 70+ raw variants
Normalization Uppercase + whitespace strip on ingest; deduplication via canonical keys at export Full taxonomy normalization — deterministic, re-runnable against updated source data
Graph models One nodes file + one edges file (attendance + connection edge types) Three distinct graph types: bipartite, co-attendance weighted, three-layer
Visualization Basic Recharts analytics (sector, location, connection type counts); no network rendering Rendered network maps (NetworkX/Matplotlib) + interactive Plotly charts
Methodology Implicit in the code Documented pipeline, each stage explicit and reproducible
